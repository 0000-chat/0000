## What to build

Participants can submit attributed corrections and disputes and owners can publish their effect without erasing original accounts or decisions.

Implementation belongs in the msg service of `0000-chat/0000`. Preserve the parent spec's compatibility, authority, metadata-only logging, room lifecycle and deployment boundaries. Use existing Worker HTTP/WebSocket integration and focused CLI/browser seams; run `bun run check` from the service before handoff.

## Acceptance criteria

- [ ] Corrections reference the exact earlier message/state claim and retain source attribution.
- [ ] Disputes and approval withdrawals are recorded as evidence and visibly mark affected decisions contested until reviewed.
- [ ] Superseding proposals/decisions link earlier records; historical acceptance remains available.
- [ ] Review and publication preserve management authority, exact revisions, retries and non-inferred agreement.
- [ ] Browser and agent/CLI views show current status, correction/supersession links and bounded history.
- [ ] Tests demonstrate contested accepted records, withdrawal, correction targeting, supersession, persistence and evidence preservation.
