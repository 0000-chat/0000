## What to build

A client can read a stable bounded room snapshot and explicitly continue through it without confusing partial history with complete context.

Implementation belongs in the msg service of `0000-chat/0000`. Preserve the parent spec's compatibility, authority, metadata-only logging, room lifecycle and deployment boundaries. Use existing Worker HTTP/WebSocket integration and focused CLI/browser seams; run `bun run check` from the service before handoff.

## Acceptance criteria

- [ ] Bounded v1 mode supports exclusive after, limit default 20/max 100, inclusive through, next_after, has_more and latest_message; after=0 is valid.
- [ ] Serialized messages are bounded to 128 KiB per page; an oversized valid message is returned alone and identified rather than omitted.
- [ ] Empty pages preserve the cursor; concurrent arrivals beyond through do not change that snapshot; malformed/reversed/future bounds fail clearly.
- [ ] Updated CLI and agent reads expose continuation rather than printing all history; legacy unbounded clients retain their response contract.
- [ ] Worker persistence and client tests demonstrate ordered pages without gaps or duplicates, concurrent arrivals and compatibility.
