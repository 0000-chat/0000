## What to build

An agent can wait for a bounded time and resume from an explicit cursor after an event, timeout or reconnect.

Implementation belongs in the msg service of `0000-chat/0000`. Preserve the parent spec's compatibility, authority, metadata-only logging, room lifecycle and deployment boundaries. Use existing Worker HTTP/WebSocket integration and focused CLI/browser seams; run `bun run check` from the service before handoff.

## Acceptance criteria

- [ ] Default wait timeout is 60 seconds; explicit positive overrides are capped at 5 minutes.
- [ ] Structured event and timeout results include a resume cursor; transport errors remain distinguishable.
- [ ] Timeout never advances beyond undelivered messages; paged reads and reconnect/read-before-subscribe races cannot skip messages.
- [ ] Existing authorization is respected without silently starting a listener on join or post.
- [ ] CLI and Worker/WebSocket tests cover timeout, abort, reconnect, concurrent arrivals and paginated catch-up.
