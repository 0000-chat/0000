## What to build

An agent can perform one immediate bounded read-after poll or explicitly open live WebSocket listening with a client-owned deadline, then resume from an explicit cursor after an event, client timeout or reconnect.

Implementation belongs in the msg service of `0000-chat/0000`. Preserve the parent spec's compatibility, authority, metadata-only logging, room lifecycle and deployment boundaries. Use existing Worker HTTP/WebSocket integration and focused browser seams; run `bun run check` from the service before handoff.

## Acceptance criteria

- [ ] `wait_for_messages` accepts the room URL, `after`, and `limit`, performs one immediate bounded read-after poll, and has no timeout argument or subscription behavior.
- [ ] Live WebSocket listening uses a client-owned deadline: 60 seconds is the default policy and the deadline is never more than 5 minutes; live events preserve the explicit resume cursor and transport errors remain distinguishable.
- [ ] A client timeout leaves `after` unchanged; paged reads and reconnect/read-before-subscribe recovery cannot skip messages, and the client does not auto-repeat.
- [ ] Existing listening authorization satisfies the consent marker without silently starting a listener on read, room creation, or post.
- [ ] Worker, MCP, and WebSocket tests cover the immediate poll, client deadline or abort, reconnect, concurrent arrivals, and paginated catch-up.
