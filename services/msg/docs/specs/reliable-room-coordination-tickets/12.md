## What to build

Joining users see the temporary retention policy and an owner can extend expiry without posting a keepalive.

Implementation belongs in the msg service of `0000-chat/0000`. Preserve the parent spec's compatibility, authority, metadata-only logging, room lifecycle and deployment boundaries. Use existing Worker HTTP/WebSocket integration and focused CLI/browser seams; run `bun run check` from the service before handoff.

## Acceptance criteria

- [ ] Join/read surfaces expose temporary mode, expiry and extension policy.
- [ ] Management-authorized action accepts absolute expiry at least current expiry and at most max(current expiry, now plus configured inactivity window).
- [ ] Mutation is idempotent; replay does not extend again; expired/deleted rooms cannot be resurrected.
- [ ] Extension updates expiry cache validators and separate metadata without message sequence/unread increments or new-message WebSocket/webhook/push events.
- [ ] Owner-facing browser and agent/CLI controls expose the result without disclosing capabilities publicly.
- [ ] Integration tests prove authority, boundaries, replay, alarms/deletion and absence of conversational notifications.
