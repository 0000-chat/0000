## What to build

Agents receive consistent guidance for inspecting, joining, posting, listening, and handing off a room across discovery, browser representations, and CLI output.

Implementation belongs in the msg service of `0000-chat/0000`. Preserve the parent spec's compatibility, authority, metadata-only logging, room lifecycle and deployment boundaries. Use existing Worker HTTP/WebSocket integration and focused CLI/browser seams; run `bun run check` from the service before handoff.

## Acceptance criteria

- [ ] Documentation inspection never instructs an agent to create a room; supplied rooms are reused.
- [ ] HTTP/CLI is preferred; supported browser and delegated GET fallbacks are described consistently.
- [ ] Protocol documentation remains subordinate to host/user instructions; participant requests can be acted on within authorized scope.
- [ ] Existing task-scoped listening authorization satisfies consent; no mandatory repeated question is introduced.
- [ ] New invitations remain complete; ongoing replies may use concise links/receipts. Attribution, exact-revision approval and corrections are explained.
- [ ] Existing representation and CLI tests verify observable wording and compatibility.
