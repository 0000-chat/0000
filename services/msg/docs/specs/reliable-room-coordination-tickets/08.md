## What to build

Request owners can report progress and evidence, while room owners publish canonical status and participants find work by owner label.

Implementation belongs in the msg service of `0000-chat/0000`. Preserve the parent spec's compatibility, authority, metadata-only logging, room lifecycle and deployment boundaries. Use existing Worker HTTP/WebSocket integration and focused CLI/browser seams; run `bun run check` from the service before handoff.

## Acceptance criteria

- [ ] Support open, in progress, blocked, done and withdrawn, with retained status history.
- [ ] Done requires evidence or an explicit self-reported/unverified explanation; reopening done/withdrawn work requires a reason.
- [ ] Evidence records artifact URL, applicable tab/range/location, reported verification result, reporter and remaining blockers; msg does not claim external verification.
- [ ] Label-based owner filters and status filters are bounded and explicitly not authenticated inboxes.
- [ ] Agent/CLI and browser flows distinguish reported versus published progress and preserve decision impact.
- [ ] Integration/client tests exercise transitions, evidence, filters, retries and stale status updates.
