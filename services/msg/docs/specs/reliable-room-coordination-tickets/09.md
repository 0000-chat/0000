## What to build

Participants can see and maintain purpose, phase, canonical documents, next actions and request summaries without downloading the transcript.

Implementation belongs in the msg service of `0000-chat/0000`. Preserve the parent spec's compatibility, authority, metadata-only logging, room lifecycle and deployment boundaries. Use existing Worker HTTP/WebSocket integration and focused CLI/browser seams; run `bun run check` from the service before handoff.

## Acceptance criteria

- [ ] Browser pinned panel and HTTP/CLI overview expose purpose, phase, published revision, bounded request summaries/counts, artifact roles, next-action owners, latest sequence and expiry.
- [ ] Participants propose changes; management reviews evidence and publishes through the existing version/retry contract.
- [ ] All collections/history are bounded with continuation or detail access; empty state is not inferred from chat.
- [ ] Cache validators change when state or expiry changes without a message; panel and agent views show matching provenance/revisions.
- [ ] No background summarization, credentials or new service dependency is introduced.
- [ ] Client/integration tests demonstrate propose-review-publish, stale edit rejection, evidence/history navigation and bounded overview.
