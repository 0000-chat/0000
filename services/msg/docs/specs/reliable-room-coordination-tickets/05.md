## What to build

A sender can opt into rejecting a reply drafted against old room context, review intervening messages, and explicitly resubmit.

Implementation belongs in the msg service of `0000-chat/0000`. Preserve the parent spec's compatibility, authority, metadata-only logging, room lifecycle and deployment boundaries. Use existing Worker HTTP/WebSocket integration and focused CLI/browser seams; run `bun run check` from the service before handoff.

## Acceptance criteria

- [ ] Optional based_on_sequence is checked atomically against the room sequence; stale writes return conflict, latest sequence and a review cursor.
- [ ] A conflict stores nothing and does not consume the retry identifier; a corrected resubmission succeeds.
- [ ] Successful idempotent replay is resolved before the stale-context check; clients omitting the precondition retain current behavior.
- [ ] Agent/CLI posting exposes the option and review/resubmit workflow without automatic approval or automatic stale submission.
- [ ] Concurrent-post integration tests prove no outdated write commits when the precondition is supplied.
